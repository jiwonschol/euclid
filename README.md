# 그라운드의 유클리드 — 연속 경기 엔진 (프로토타입)

**축구라는 전술 보드게임판을 보며, 감독(유저)이 컴퓨터의 수에 카드로 대응하는 게임.**
경기 장면은 물리 재현이 아니라 *대응이 읽히는 하이라이트*이고, 진짜 경기는 **실시간 중계(글)**를 근거로 한 유저의 상상에서 벌어진다. 바둑알 판은 그 실현·보조다.

> **제1원칙(모든 문서보다 먼저): [docs/first_principle.md](docs/first_principle.md)** — 축구 엔진은 진형을 그리는 게 아니라 '골'이라는 목적에서 행동을 유도한다. 진형은 입력이 아니라 결과다.
> 정본 설계: [docs/match_engine_v1_plan.md](docs/match_engine_v1_plan.md) (§0.1 게임 정체성 필독)
> 마스터 계획서: `docs/captain_tsubasa_card_manager_claude_code_prompt.md`

## 실행

브라우저 보안(파일 직접 열기 시 JSON 로드 불가) 때문에 작은 로컬 서버가 필요하다(설치 불필요, 맥 기본 파이썬).

- 터미널: `npm start` → **<http://localhost:8642/viewer.html>**
- 또는 `start.command` 더블클릭.

## 플레이 방법 (뷰어)

1. **중계 피드(좌)** 와 **스탯 바**(점유율·모멘텀·유효슈팅·xG·코너)를 읽는다 — 경기의 근거는 글이다.
2. **빌드업 구간**에는 바둑알이 흐려지고 🔍 힌트 중계만 나온다. *그 구간이 곧 유저가 반응할 시간이고,
   그게 이 게임의 문법이다.* 파이널서드에 패스가 쌓이면 **하이라이트**로 전환돼 바둑알이 켜진다.
3. **스탠스 5그룹 × 3열**을 고른다. 각 그룹은 **밸런스(기본) + 상반된 둘**이고, 한 그룹에 하나만 활성이다.

   | 그룹 | 밸런스 | 상반 |
   |---|---|---|
   | 공격 방향 | 밸런스 | 측면 공격 ↔ 중앙 공격 |
   | 경기 성향 | 밸런스 | 역습 대기 ↔ 전원 공격 |
   | 수비 라인 | 밸런스 | 라인 올리기 ↔ 라인 내리기 |
   | 압박 | 밸런스 | 높은 압박 ↔ 낮은 압박 |
   | 수비 방향 | 밸런스 | 중앙 수비 ↔ 측면 수비 |

4. **핵심 문법은 읽고 대응이다.** '수비 방향'이 상대의 **실제** 공격 방향과 맞으면 탈취 확률 1.45배,
   밸런스 1.0배, 빗맞히면 0.65배 — 카드가 실제로 결과를 바꾼다.
5. 카드는 즉시가 아니라 **'전달 중'(2초)** 을 거쳐 도착한다. 도착 전이면 다른 선택으로 **교체(오디블)** 할 수 있다.
6. **참모**가 경기당 30~40회 개입해 *직접적이고 행동 가능한* 정보를 준다("상대가 측면을 집요하게
   노리는데요"). `[조언 받아들이기]` 한 번이면 그 스탠스가 그대로 들어간다.
7. **교체 3장**(공격수/미드필더/수비수): 역할별 0~35% 상승. 투입 후 시퀀스 중 언젠가 결과를 알린다.
8. 상단 컨트롤: 재생·일시정지·속도(1~4×)·새 경기.

> **CP·덱·드로우·손패·맥락 카드는 폐기됐다**(2026-07-15 디자이너: 복잡도만 늘렸다).
> 지금은 위의 상반 스탠스뿐이다.

## 밸런스·문구 조정 (디자이너용)

코드 없이 `data/*.json`만 고치면 된다(새로고침으로 반영):

| 파일 | 내용 |
|---|---|
| `data/engine.json` | 선수 운동학·형상·압박·1대1 경합·몸·GK·공 물리·utility AI (실제 축구 m/s·m 단위) |
| `data/stance.json` | 스탠스 5그룹 × 3열·전달 시간·참모 힌트·상대 감독 AI·경기 길이 |
| `data/commentary.json` | 실시간 중계 템플릿 — 흐름/압박/영역/측면/역습/이벤트/스탯 (조사 `#가/#는/#를` 자동) |
| `data/policy.json` | **사람이 손대지 않는다.** 자기대국이 찾은 정책 계수(오프볼·캐리어·GK·수비·경합) |

## 검증 (헤드리스 게이트)

```
npm run sim:match      # Stage 1 골격: 좌표·22명·시계·단계머신·시드 재현
npm run sim:pos        # Stage 2 포지셔닝: 몰림방지·압박≤2·역습대비·폭·측면추종·속도캡
npm run sim:play       # Stage 3 창발경기: 순간이동 없음·양팀 점유·방향편향 없음·재현성
npm run sim:offside    # §10 오프사이드 판정 단위테스트 (Law 11 — 대상은 팀이 아니라 사람)
npm run sim:rules      # §11 반칙 계층: 태클 resolver·프리킥·PK·옐로2=레드·퇴장 불변조건
npm run sim:stance     # 스탠스 카드: 전달중/오디블·threatMul·빌드업/하이라이트·참모·교체 (36검사)
npm run sim:stability  # 100경기 풀스택·예외/NaN/데드락 0·재현성 (~2분)
npm run sim:realism    # 축구다움 눈금 M1~M4 (정책 ON. 목표가 아니라 검증 도구다)
npm run sim:seq        # 슛 전 패스 수 분포 — 2026-07-15 목표. 제1원칙과 충돌해 **디자이너 결정 대기**
```

숫자가 이상할 때는 눈금이 아니라 **소유 해부**를 본다 — 눈금은 *무엇이* 어긋났는지,
해부는 *왜* 그런지를 말한다. 이 저장소에서 진짜 원인을 찾아낸 건 언제나 이쪽이었다.

```
npm run sim:diagnose -- 3                 # 학습된 정책으로
npm run sim:diagnose -- 3 --no-policy     # 레거시(손으로 쓴 효용) 경로와 대조
```

정책 학습:

```
node sim/selfplay.mjs --gens 400 --pop 8 --matches 6 --half 300 --workers 8
```

## 구조

- `js/game/*` — 순수 연속 시뮬 코어(DOM 없음, 브라우저·헤드리스 공유). 15Hz 고정 타임스텝, 시드 결정론.
  - **경기**: `match.js` 상태·단계머신 · `field.js` 피치 기하 · `movement.js` 운동학 ·
    `ball.js` 공 물리 · `decide.js` 소유·캐리어 결정·득점·오프사이드·반칙·재개 · `commentary.js` 중계
  - **포지셔닝**: `ai.js` 매 틱 배치 · `shape.js` 팀 형상(약한 prior) ·
    `attack.js` 침투·서포트·오버랩 · `defend.js` 마킹
  - **학습되는 정책**(계수는 사람이 고르지 않는다 — `docs/first_principle.md`):
    `policy.js` 신경망 · `value.js`/`offball.js` 오프-볼 가치 · `carrier.js` 캐리어 행동 ·
    `gk.js` GK(§9) · `defball.js` 수비 오프-볼 · `duel.js` 1대1 경합
  - **게임 문법 층**: `effects.js` 효과 엔진(modifier resolve·스택·지속) · `stance.js` 상반 스탠스·
    전달중/오디블·참모·상대 감독 AI·빌드업/하이라이트
- `js/ui/pitch2d.js` — 미터 좌표 → 캔버스 (보조 시각화)
- `viewer.html` — 중계 피드·스탯·스탠스 3열 그리드 (텍스트 1차 표면)
- `data/*.json` — 튜너블·문구 (디자이너 영역)
- `sim/*.mjs` — 게이트 + 자기대국(`selfplay.mjs`, `selfplay-eval.mjs`, `selfplay-worker.mjs`)

## 알려진 한계 (정직하게)

- **골이 실제(2.7/경기)보다 훨씬 많다.** 학습된 정책이 아직 '골 에어리어까지 걸어 들어가 슛'을
  이득으로 본다 — 박스 안 수비 인원이 실제 축구(4~8명)에 못 미치기 때문이고, 자기대국이 값을
  매겨야 할 지점이다. 여기에 '슛 상한' 필터를 넣는 것은 규칙의 구멍을 필터로 가리는 짓이다
  (`docs/first_principle.md`).
- `sim:seq`(슛 전 패스 분포) 빨강 — 분포를 강제하는 기제와 제1원칙이 충돌한다. 디자이너 결정 대기.
- 레거시 게이트(`sim:match/pos/play/rules`)는 정책을 넘기지 않아 **학습된 엔진이 아니라 손으로 쓴
  옛 효용 경로**를 검증한다. 그 경로는 지금 슛 18·골 7 로 실축에 가깝다.
- §4 능력치는 역할별 평균 + 결정론 지터까지만(선수 개별 22항목은 디자이너가 보류시킴).
- 연장·승부차기 미구현. 시네마틱 확대 연출은 중계 텍스트로 대체(정체성상 텍스트 우선).
