# 그라운드의 유클리드

큰 축구 장면을 보고 감독 지시를 선택하는 로컬 2D 게임 프로토타입이다. 공격·수비 각각 세 카드와 기본 유지가 선수 이동, 다음 패스 후보, 남겨진 공간과 경기시간을 바꾼다. 22명 전술 필드와 큰 장면은 같은 판정 기록을 보여준다.

## 실행과 조작

`npm start` 후 **http://localhost:8642/** 를 연다. Python 3와 Node.js를 사용하며 추가 패키지 설치는 필요 없다. macOS에서는 `start.command`도 사용할 수 있다.

- 카드를 누르면 즉시 확정한다. 지시 이름 → 이동 선수 → 홍림 → 청해 → 공/얼굴 → 실제 결과를 짧게 보여준다. 입력이 없으면 6초 후 기본 유지로 진행한다.
- `1`–`3`: 즉시 카드 확정, `←`/`→`: 측면, `Enter`/`Esc`: 기본 유지로 진행, `Space`: 일시정지.
- 1×/2×/4×와 결과 스킵은 판정을 바꾸지 않는다. 명령창은 배속과 관계없이 6초다.
- 한 국면의 선택 외 재생은 6.5초다. 한 경기에는 전후반과 20~28국면이 있고, 무입력 1배속도 6분 안에 끝난다. 새로고침하면 저장된 경기가 일시정지 상태로 복원된다.
- 첫 화면의 **첫 세 국면**은 무입력 약 39.5초다. 두 선택을 나란히 보는 비교 화면은 [director-lab.html](director-lab.html)이다.

공격 지시는 측면 지원·반대쪽 전환·중앙 침투, 수비 지시는 측면 압박·중앙 차단·후퇴 지연이다. 카드는 확률 보너스를 직접 더하지 않는다. 바뀐 선수 위치와 행동을 공통 판정기가 처리한다.

## 검증과 현재 한계

`npm run test:director:quick`은 핵심 계약·카드별 이득/대가·에셋 연결을 검사한다. `npm run test:director`는 여기에 400경기 완주와 320회 결정론 비교를 포함한다. 실행 증거와 남은 일은 [진행 문서](docs/director-progress.md), 구현 계약은 [정본 계획](docs/director_game_plan.md)을 본다.

현재 판정 버전은 `director-1.0.2`이다. 같은 판정 버전·규칙에서 시드와 명령 기록이 같으면 결과가 같다. 판정 버전이나 진행 시간 설정이 달라진 저장은 자동 변환하지 않는다. 이전 기록을 내보내거나 새 경기를 시작할 수 있다. 이번 화면 변경의 기준은 [이슈 #19](https://github.com/jiwonschol/euclid/issues/19)와 [경기 문법 조사](docs/reference/captain_tsubasa_match_grammar.md)다. 기존 계획의 24초 국면·예약 후 확정 계약은 이 지시로 교체됐다.

기술 검증과 재미 검증은 구분한다. 고정 시드 400경기에서 합계 1,026회 슛·341골이 발생했다. 경기당 약 2.57회 슛·0.85골이며, 청해와 홍림의 합계도 비대칭이다. 네 입력 전략과 상대 프로필을 섞은 검사이므로 승률 균형을 증명하지 않는다. **공격 기회와 선택의 재미는 사람 플레이 평가가 남아 있다.**

Higgsfield로 생성한 이미지 25개의 WebP 배포본이 경기 화면에 연결돼 있다. 배포본 합계는 약 7.35 MiB이며, 원본 PNG는 편집·출처 확인용으로 보존한다. 한 장씩 전환하는 포즈의 동작·킥 접촉·배경 연속성에는 한계가 있다. 시즌·온라인·선수 교체·경고/퇴장·피로는 이번 범위에 없다.

## 소스와 연구 경로

- `js/director/`: 상태, 감독 지시, 상대 준비, 판정, 경기 진행, 화면 연결.
- `js/ui/scene-player.js`: 판정 기록으로 장면과 전술 필드를 그린다.
- `data/director/rules.json`: 판정과 진행의 조정값.
- `assets/director/manifest.json`: 생성 에셋 출처·크기·해시·배치 기준점. [제작 노트](assets/director/production-notes.md), [예산 장부](docs/director-probes/generation-ledger.json).
- 기존 연구 화면은 [viewer.html](viewer.html), 당시 안내는 [연구 README](docs/legacy_research_readme.md)에 보존했다. `js/game/` 연구 엔진은 새 제품의 완료 조건이 아니다.
