# 그라운드의 유클리드 — 연속 경기 엔진 (프로토타입)

**축구라는 전술 보드게임판을 보며, 감독(유저)이 컴퓨터의 수에 카드로 대응하는 게임.**
경기 장면은 물리 재현이 아니라 *대응이 읽히는 하이라이트*이고, 진짜 경기는 **실시간 중계(글)**를 근거로 한 유저의 상상에서 벌어진다. 바둑알 판은 그 실현·보조다.

> 정본 설계: [docs/match_engine_v1_plan.md](docs/match_engine_v1_plan.md) (§0.1 게임 정체성 필독)
> 마스터 계획서: `docs/captain_tsubasa_card_manager_claude_code_prompt.md`

## 실행

브라우저 보안(파일 직접 열기 시 JSON 로드 불가) 때문에 작은 로컬 서버가 필요하다(설치 불필요, 맥 기본 파이썬).

- 터미널: `npm start` → **<http://localhost:8642/viewer.html>**
- 또는 `start.command` 더블클릭.

## 플레이 방법 (뷰어)

1. **중계 피드(좌)** 와 **스탯 바(점유율·모멘텀·유효슈팅)** 를 읽는다 — 경기의 근거는 글이다.
2. **김성주 신호**를 주시한다: 컴퓨터(인천)가 전술을 바꾸기 전 "🎙 김성주: 인천이 공격 대형을 준비하는 것 같습니다. 뒷공간을 조심하세요." 같이 예고한다.
3. **지시 카드**를 낸다(CP 소모). 카드는 즉시 반영이 아니라 **'전달 중'** 을 거쳐 도착한다.
4. **오디블**: 전달 중인 지시는 다른 카드로 **교체**할 수 있고, **비용은 1회만** 든다(공격 → 역습으로 바꿔도 2회 소모 아님). 김성주 신호를 읽고 마지막 순간에 바꾸는 게 핵심 재미.
5. **교체 3종**(공격수/미드필더/수비수)은 즉시 반영(총 3회): 슛 정확도↑ / 볼 지키기↑ / 실점 위험↓.
6. 상단 컨트롤: 재생·일시정지·속도(1~4×)·새 경기.

## 밸런스·문구 조정 (디자이너용)

코드 없이 `data/*.json`만 고치면 된다(새로고침으로 반영):

| 파일 | 내용 |
|---|---|
| `data/engine.json` | 선수 운동학·형상·압박·GK·공 물리·utility AI 가중치 (실제 축구 m/s·m 단위) |
| `data/commentary.json` | 실시간 중계 템플릿 — 흐름/이벤트/스탯/김성주 신호. 문구만 늘리면 다양성↑(조사 `#가/#는` 자동) |
| `data/cards.json` | 지시 카드·CP·전달 시간·오디블·교체·상대 AI |

## 검증 (헤드리스 게이트)

```
npm run sim:match      # Stage 1 골격: 좌표·22명·시계·단계머신·시드 재현 (16검사)
npm run sim:pos        # Stage 2 포지셔닝: 몰림방지·압박≤2·역습대비·폭·측면추종·속도캡
npm run sim:play       # Stage 3 창발경기: 순간이동 없음·양팀 점유·패스/슛·방향편향 없음·재현성
npm run sim:stability  # Stage 8 안정성: 100경기 풀스택(카드·상대AI)·예외/NaN/데드락 0·재현성 (~4분)
```

## 구조

- `js/game/*` — 순수 연속 시뮬 코어(DOM 없음, 브라우저·헤드리스 공유). 15Hz 고정 타임스텝, 시드 결정론.
  - `match.js` 상태·단계머신 · `movement.js` 운동학 · `shape.js` 팀 형상 · `ai.js` 포지셔닝 ·
    `ball.js` 공 물리 · `decide.js` utility AI·득점·오프사이드·재개 · `commentary.js` 중계 · `directives.js` 카드·상대AI
- `js/ui/pitch2d.js` — 미터 좌표 → 캔버스 (보조 시각화)
- `viewer.html` — 중계 피드·스탯·카드 손패 (텍스트 1차 표면)
- `data/*.json` — 튜너블·문구 (디자이너 영역)
- `sim/*.mjs` — 게이트

## 알려진 한계 (프로토타입)

- 골이 실제(≈2.6/경기)보다 다소 많다(≈5~7). 밸런스는 `data/engine.json`·`cards.json` 튜닝으로 계속 조정.
- 반칙/카드(옐로·레드)·연장·승부차기 미구현. GK는 실용 선방/배급 수준(정밀 모델 아님).
- 시네마틱 확대 연출은 중계 텍스트로 대체(정체성상 텍스트 우선).
