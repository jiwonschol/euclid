# 그라운드의 유클리드 — 축구 장면과 감독 카드

**큰 축구 장면을 보고, 감독의 카드가 다음 선수 행동과 위험을 바꾸는 게임을 만든다.**
2026-09-22 제품 방향은 캡틴츠바사 4의 경기 문법을 참고한다. 현재는 계획과 이미지 제작 경로를 검토한 단계이며, 새 게임 구현은 아직 시작하지 않았다.

> **제품 실행 정본: [docs/director_game_plan.md](docs/director_game_plan.md)** — 범위, 여섯 지시, 판정과 장면, 단계별 완료 게이트, 무인 실행 프롬프트를 포함한다.
> 이미지: [제작 기록](docs/director-probes/README.md) · [합성 확인](docs/director-probes/preview.html)
> `first_principle.md`와 기존 엔진 계획은 연속 시뮬레이션 연구 경로의 역사 자료다. 새 제품과 충돌하면 위 계획을 따른다.

아래 실행·조작·검사 설명은 **이 브랜치의 기존 연구 프로토타입 기록**이다. 오래된 CP·손패·완료 수치 등을 새 제품 요구나 현재 검증 결과로 사용하지 않는다. 구현은 최신 main에서 시작하고 새 진입점은 M6에서 전환한다.

## 실행

브라우저 보안(파일 직접 열기 시 JSON 로드 불가) 때문에 작은 로컬 서버가 필요하다(설치 불필요, 맥 기본 파이썬).

- 터미널: `npm start` → **<http://localhost:8642/viewer.html>**
- 또는 `start.command` 더블클릭.

## 플레이 방법 (뷰어)

1. **중계 피드(좌)** 와 **스탯 바(점유율·모멘텀·유효슈팅)** 를 읽는다 — 경기의 근거는 글이다.
2. **김성주 신호**를 주시한다: 컴퓨터(인천)가 전술을 바꾸기 전 "🎙 김성주: 인천이 공격 대형을 준비하는 것 같습니다. 뒷공간을 조심하세요." 같이 예고한다.
3. **손패 카드**를 낸다: 덱에서 뽑은 감독 카드(하스스톤형 손패). 각 카드는 **비용(CP)·효과·타이밍·지속시간**을 가진다(높은 압박 20초, 침투 패스, 전원 공격, 밀착 마크…). CP는 시간마다 회복되고 볼을 되찾으면 보너스. 카드는 즉시가 아니라 **'전달 중'** 을 거쳐 도착해 효과가 발동한다.
4. **못 내는 카드는 흐려지고**, 마우스를 올리면 이유가 뜬다("공격 중만 · 온사이드 침투자 없음 · CP 부족 · 재사용 대기 N초"). 카드가 없어도/안 내도 선수는 알아서 패스·드리블·슛·수비한다 — 카드는 확률·우선순위·포지셔닝만 바꾼다.
5. **오디블**: 전달 중인 지시는 다른 카드로 **교체**하고 **비용은 1회만** 든다. 김성주 신호를 읽고 마지막 순간에 바꾸는 게 핵심 재미.
6. **맥락 카드**(금색): 파이널서드에서 압박받는 등 큰 순간에 손패에 잠깐 나타난다(드리블 강행/안전 패스/원투/즉시 슛). 즉시 적용되고 순간이 지나면 사라진다.
7. **교체 3종**(공격수/미드필더/수비수)은 즉시 반영(총 3회): 슛 정확도↑ / 볼 지키기↑ / 실점 위험↓.
8. 상단 컨트롤: 재생·일시정지·속도(1~4×)·새 경기.

## 밸런스·문구 조정 (디자이너용)

코드 없이 `data/*.json`만 고치면 된다(새로고침으로 반영):

| 파일 | 내용 |
|---|---|
| `data/engine.json` | 선수 운동학·형상·압박·GK·공 물리·utility AI 가중치 (실제 축구 m/s·m 단위) |
| `data/commentary.json` | 실시간 중계 템플릿 — 흐름/이벤트/스탯/김성주 신호. 문구만 늘리면 다양성↑(조사 `#가/#는` 자동) |
| `data/cards.json` | 감독 카드 덱(16장 CoachCard: 비용·타이밍·타겟·지속·효과 modifier[])·맥락 카드·CP·드로우·교체·상대 AI |

## 검증 (헤드리스 게이트)

```
npm run sim:match      # Stage 1 골격: 좌표·22명·시계·단계머신·시드 재현 (16검사)
npm run sim:pos        # Stage 2 포지셔닝: 몰림방지·압박≤2·역습대비·폭·측면추종·속도캡
npm run sim:play       # Stage 3 창발경기: 순간이동 없음·양팀 점유·패스/슛·방향편향 없음·재현성
npm run sim:cards      # 카드: 효과엔진(modifier)·validator·덱/손패·전달중/오디블·맥락·commitForward·상대AI·결정론 (59검사)
npm run sim:stability  # Stage 8 안정성: 100경기 풀스택(카드·상대AI)·예외/NaN/데드락 0·재현성 (~2분)
```

## 구조

- `js/game/*` — 순수 연속 시뮬 코어(DOM 없음, 브라우저·헤드리스 공유). 15Hz 고정 타임스텝, 시드 결정론.
  - 경기: `match.js` 상태·단계머신 · `movement.js` 운동학 · `shape.js` 팀 형상 · `ai.js` 포지셔닝 ·
    `attack.js`/`defend.js` 오프-볼 침투·마킹 · `ball.js` 공 물리 · `decide.js` utility AI·득점·오프사이드·재개 · `commentary.js` 중계
  - 카드(하스스톤형): `effects.js` 데이터 기반 효과 엔진(modifier resolve·스택·지속시간) · `cards.js` 검증(타이밍/CP/타겟/전제조건/쿨다운) ·
    `hand.js` 덱·손패·드로우·전달중/오디블·맥락 카드·CP·상대 감독 AI. 카드 무작위는 별도 `cardRng`로 시뮬 재현과 분리.
- `js/ui/pitch2d.js` — 미터 좌표 → 캔버스 (보조 시각화)
- `viewer.html` — 중계 피드·스탯·카드 손패 (텍스트 1차 표면)
- `data/*.json` — 튜너블·문구 (디자이너 영역)
- `sim/*.mjs` — 게이트

## 알려진 한계 (프로토타입)

- 골이 실제(≈2.6/경기)보다 다소 많다(카드 풀스택 ≈6~8). 밸런스는 `data/engine.json`·`cards.json` 튜닝으로 계속 조정.
- 반칙/카드(옐로·레드)·연장·승부차기 미구현. GK는 실용 선방/배급 수준(정밀 모델 아님).
- 시네마틱 확대 연출은 중계 텍스트로 대체(정체성상 텍스트 우선).
- 밀착 마크는 **클릭 타겟팅**: 카드를 누르면 마크할 상대(빨강)를 클릭해 지정한다(Esc 취소). 마크 중인 선수는 분홍 링으로 표시. 부채꼴 hover 확대는 후속.
