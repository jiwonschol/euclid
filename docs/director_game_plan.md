# 유클리드 — 장면과 감독 카드로 완성하는 장기 실행 계획

상태: **2026-09-22 지원이 GitHub 이슈 등록 및 M0~M6 구현 시작 승인. 로컬 구현 진행 중.**

이 문서는 지원의 2026-09-22 결정, 저장소 조사, 게임 문법·실행 구조·아트 제작을 맡은 서브에이전트 3개의 독립 검토를 통합한다. 지원은 실시간으로 작업을 지켜보지 않을 수 있다. 구현자는 아래의 기본값·범위·완료 게이트로 진행하고, 과거 문서를 다시 조합해 다른 제품을 만들지 않는다.

## 1. 만드는 게임과 성공의 뜻

**캡틴츠바사 4처럼 중요한 축구 행동이 크게 보이고, 감독이 낸 카드 때문에 다음 국면의 선수 행동과 위험이 달라지는 반실시간 게임.**

한 경기의 핵심 경험은 `상대 움직임을 읽는다 → 어디에 힘을 쓸지 고른다 → 지시가 도착한다 → 선수들이 다르게 움직인다 → 결과와 대가를 본다`이다. 카드 없이도 선수는 경기를 계속한다. 사용자는 매 패스·슛을 직접 조작하지 않는다.

실축 엔진 완성, 자기대국 모델의 발전, 실축 평균 통계 재현은 이 제품의 선행 조건이 아니다. 축구를 설명하는 데 필요한 상태의 연속성과 규칙은 지킨다. 예를 들어 공을 빼앗긴 위치, 전진한 풀백의 복귀, 득점 뒤 상대 킥오프가 다음 장면에 남아야 한다.

MVP가 완료되려면 시작부터 전후반·종료·복기까지 한 경기가 돌아가고, 여섯 지시 각각의 이득과 대가가 실제 화면과 판정 기록에서 확인되어야 한다. 자동 검사 통과는 기술적 완료다. 재미와 이해 가능성은 별도의 사람 검증 결과로 표시한다.

## 2. MVP의 크기와 경계

포함: 오리지널 두 팀, 팀당 11명과 GK 구분, 한 경기, 6개 감독 지시, 기본 유지, 공격·수비·전환, 최소한의 재개, 하프타임, 결과 복기, 생성 이미지, 키보드·클릭 조작, 일시정지·배속·결과 스킵, 시드와 명령 기록 재생.

제외: 3D, 22인 연속 물리 완성, 자기대국 재학습, 온라인 대전·서버, 시즌·이적·성장·수집, CP·드로우, 개별 얼굴 22종, 풀보이스, 매 장면 생성 영상, 모바일 전용 레이아웃, 연장·승부차기. 새 외부 패키지는 기본적으로 필요하지 않다.

교체·체력·부상·경고/퇴장 누적·특수기술은 MVP 이후 L1에서 다룬다. MVP의 반칙은 프리킥/PK 재개까지만 포함하며 인원수는 11명을 유지한다. 기능 없는 교체 버튼, 가짜 체력, 연결되지 않은 거츠 설명을 노출하지 않는다. 첫 경기 종료에서 무승부는 정상 결과다.

### 2.1 최초 60~90초 수직 슬라이스

`왼쪽에서 공을 받음 → 상대가 볼 소유자에게 붙음 → 측면 지원/반대쪽 전환/유지 → 지원 또는 전환 시도 → 패스 성공 혹은 차단 → 직전 지시 때문에 생긴 수비 공간을 이어받음 → 중앙 차단/후퇴 지연/유지 → 공격 저지 또는 슈팅 → 결과 설명`을 한 번 연결한다.

관측과 선택은 실제 상태를 사용한다. 판정 이후 다음 장면을 임의로 초기화하지 않는다. 기본 시연은 READY 10초 + 3국면 × 24초 = **82초**로 준비한다. 자연스러운 소유 전환이 실제 판정에서 발생하는 시작 상태·시드를 고른다. 비교 경로에서 공격이 계속되면 그 차이도 그대로 보여주며 수비 장면을 만들려고 소유를 강제로 넘기지 않는다. 수비 두 선택의 비교는 공통 수비 시작 스냅샷도 별도로 제공한다. 처음에는 같은 시작 상태와 시드에서 카드만 바꾼 두 진행을 나란히 재생할 수 있게 한다. 이 슬라이스가 읽히기 전에는 카드·컷신·팀 수를 늘리지 않는다.

## 3. 경기 진행과 세 종류의 시간

### 3.1 단일 상태 전이

`READY → FLOW → COMMAND → RESOLVE → PRESENT → ADVANCE → FLOW`

전반 끝에서는 `ADVANCE → HALFTIME → FLOW`, 경기 끝에서는 `ADVANCE → FULLTIME → REVIEW`로 간다. 재시작은 새 `sessionId`로 READY를 만든다. 이전 세션의 입력·이미지 완료·타이머는 새 세션에 작용하지 않는다.

| 단계 | 1배속 기본 길이 | 할 일과 입력 |
|---|---:|---|
| READY | 10초 | 팀과 여섯 지시를 짧게 소개. 즉시 시작 가능. |
| FLOW | 12초 | 직전 상태에서 이어지는 운반·지원 이동·기본 전개를 보여준다. 다음 국면과 상대 준비가 읽힌다. 다음 지시를 예약할 수 있다. |
| COMMAND | 실제 6초 | 판정 전 최종 관측 상태를 고정. 주변 대기 동작은 재생. 예약 교체·취소 가능. 기본 유지 버튼으로 일찍 확정할 수도 있다. |
| RESOLVE | 논리 단계 | 최종 합법성 검사, 상대의 사전 의도와 사용자 지시 잠금, 한 번 판정·커밋. 애니메이션을 기다리지 않는다. |
| PRESENT | 5초 | 기록된 2~4개 핵심 행동 비트를 재생. 카드 변경 불가. 결과 스킵 가능. |
| ADVANCE | 1초 | 최종 상태·시계·결과를 공개하고 다음 국면 또는 전후반 경계로 이동. 재판정하지 않는다. |
| HALFTIME | 기본 10초 | 실제 사건 요약, 다음 전술을 예약하는 슬롯 하나. 계속 버튼·일시정지 제공. 기본 자동 진행. |
| FULLTIME | 논리 단계 | 종료 사건을 한 번 남기고 최종 집계를 고정한 뒤 REVIEW로 이동. 새 경합 없음. |
| REVIEW | 제한 없음 | 최종 점수, 선택과 실제 효과·대가, 같은 시드 재경기·새 경기. |

한 국면은 FLOW 시작부터 ADVANCE 종료까지다. 카드의 행동 지시는 해당 국면의 RESOLVE에서 생성하는 행동 묶음에만 적용한다. 지시가 만든 위치·소유·노출은 다음 상태로 남는다. 효과 배수만 다음 국면에 몰래 남기지 않는다.

FLOW에서 보여주는 자동 전개도 사건/포즈 타임라인으로 기록한다. MVP의 FLOW는 **소유를 바꾸지 않는 경합 없는 운반·지원 준비**로 제한하고, 패스·차단·돌파·슛은 RESOLVE에 둔다. `prepareEncounter()`는 직전 상태에서 이동 가능한 목표점과 `flowPlan`을 만들고, 코어가 COMMAND 진입 때 그 도착 상태를 한 번 반영한다. 화면은 같은 flowPlan을 보간할 뿐 위치를 별도로 계산하지 않는다. 경합 영역에 닿으면 더 전진하지 않고 다음 판정을 기다린다. 따라서 렌더링 프레임 수와 무관하게 COMMAND의 snapshot과 beforeHash가 같다.

카드의 대상은 화면에 명시된 **이번 국면의 아직 판정하지 않은 경합**이다. FLOW 예약은 그 다음 COMMAND에서 관측되는 대상에 대한 예약이며, 이미 기록된 준비 이동을 소급 변경하지 않는다. 예약의 합법성은 COMMAND 진입·확정 때 다시 검사한다. 대상이 무효가 되면 취소 이유를 표시하고 COMMAND 6초를 온전히 제공한다. 무입력일 때도 기본 행동을 판정하므로 경기는 계속된다.

### 3.2 단위와 페이싱 공식

- `matchSeconds`: 표시상 축구 시간. 0~5400, 전반 종료 2700. 경기 판단·막판 전략은 이것만 사용한다.
- `encounterIndex`: 판정한 국면의 순번. 전달·효과 만료·상대 반응을 표현한다.
- `presentationSeconds`: 화면과 선택 창의 실제 시간. 경기 난수·점수 계산에 들어가지 않는다.

국면 하나가 대표하는 경기시간은 `delta = clamp(225 + tempoDeltaSeconds, 200, 270)`으로 시작한다. 이는 생략된 평범한 경기 시간을 포함하는 **게임용 압축**이며 실제 공 비행 시간이 아니다. 사용자와 상대가 선택한 지시 중 **공격팀 지시**의 tempo 보정만 적용한다. 반대쪽 전환 +30초, 중앙 침투 -15초, 나머지 0초다. 카드 없이 유지도 0초다.

남은 전반/후반 시간이 delta보다 짧으면 마지막 delta를 그 경계에 맞춘다. 이 clamp에서 허용되는 범위는 반당 10~14국면, 경기당 20~28국면이다. 기본 24초 × 국면 수 + READY 10초 + HALFTIME 10초 = **8분20초~11분32초**가 전체 페이싱 한계다. 현재 카드의 실제 delta 210/225/255만 쓰면 22~26국면, 9분08초~10분44초로 더 좁아진다. 일시정지·복기 시간은 제외하고 조기 확정·스킵·배속 사용 시 더 짧아진다. 점수에 맞춰 delta나 득점 확률을 바꾸지 않는다. 반칙·재개 때문에 별도의 0초 국면을 무한히 추가하지 않는다.

RESOLVE는 `nextState.matchSeconds`까지 한 번 계산해 커밋한다. PRESENT의 점수판·미니맵·시계는 해당 기록의 공개된 비트까지만 보여주는 projection이다. 표시 시계의 최종 delta 반영은 ADVANCE에 공개한다. 미리 계산한 골이 슛 장면 전에 보이지 않게 한다. UI는 score/time의 별도 정본을 소유하지 않는다.

배속 1×/2×/4×는 FLOW·PRESENT·ADVANCE에만 적용한다. COMMAND는 언제나 실제 6초, READY/HALFTIME도 배속과 분리한다. 일시정지는 모든 화면·선택 타이머를 멈추지만 완료된 판정을 되돌리지 않는다. 백그라운드 탭에서는 자동 일시정지하며 복귀 때 밀린 시간을 한꺼번에 소비하지 않는다. 스킵은 PRESENT의 마지막 비트로 이동할 뿐 추가 RNG·득점·카드 적용을 만들지 않는다.

## 4. 여섯 카드의 의미 계약

모든 카드는 무제한 보유하는 고정 선택지다. 공격 때 공격 3장, 수비 때 수비 3장이 유효하며 반대쪽 카드는 이유와 함께 비활성화한다. 기본 유지는 항상 가능하다. 측면 카드의 대상은 클릭 또는 방향키로 왼쪽/오른쪽 한 곳을 고르고, 기본값은 현재 공이 있는 측면이다. 중앙에 있으면 패널에 선택된 쪽을 명시하며 임의로 바꾸지 않는다.

| ID / 카드 | 가능한 상황 | 반드시 달라지는 행동 | 포기하는 것·다음 상태의 대가 | tempo |
|---|---|---|---|---:|
| `support_flank` 측면 지원 | 공격, 해당 측면 지원 역할 출전 중 | 지원 선수가 합류해 기존에 없던 합법적 패스 후보를 만든다 | 올라간 선수의 뒤 공간과 복귀 지연이 소유 전환 뒤에도 남음 | 0 |
| `switch_play` 반대쪽 전환 | 공격, 반대편 합법적 연결 후보 존재 | 반대 측면 연결을 우선해 공격 구역을 이동 | 긴 패스의 차단 가능성, 더 많은 경기시간 소비 | +30초 |
| `run_inside` 중앙 침투 | 공격, 온사이드 러너 존재 | 중앙 러너의 움직임과 연결 후보를 우선 | 중앙 턴오버 시 즉시 역습 경로가 열림 | -15초 |
| `press_flank` 측면 압박 | 수비, 해당 측면 압박·지원 가능 | 압박자와 지원자가 그쪽 볼 소유자에게 접근 | 중앙/반대쪽 커버 감소, 뚫렸을 때 복귀 지연 | 0 |
| `screen_middle` 중앙 차단 | 수비, 중앙 커버 가능 | 중앙 패스·컷백 길을 우선해 위치를 잡음 | 상대 측면 운반·크로스 공간 허용 | 0 |
| `delay_drop` 후퇴 지연 | 수비 | 달려들기보다 골 방향 복귀·커버 우선 | 즉시 탈취 기회 포기, 상대의 전진 허용 | 0 |

‘가능’은 조건을 갖춘 **시도**를 뜻한다. 특정 카드가 패스 성공·득점·탈취를 보장하지 않는다. 카드별 `+골 확률`이나 정답 카드와 오답 카드에 대응하는 완성 결과표로 구현하지 않는다. 카드가 바꾸는 것은 위치, 행동 후보, 행동 우선순위와 위험 노출이다. 그 뒤 동일한 경합 규칙으로 판정한다.

### 4.1 예약·확정·무효

1. FLOW/COMMAND 동안 `pendingCommand` 하나만 둔다. 새 카드는 이전 예약을 **교체**한다. UI는 하나의 예약 슬롯만 보여준다.
2. 확정 전 취소는 기본 유지로 돌아간다. 여러 카드가 ‘적용됨’으로 표시되는 상태는 없다.
3. COMMAND 종료 또는 사용자 확정에서 대상을 재검사한다. 무효면 이유를 남기고 기본 유지로 진행한다. 자동으로 다른 카드나 대상을 고르지 않는다.
4. `(sessionId, encounterId, commandId)`가 같은 제출은 한 번만 처리한다. 확정 뒤 입력은 비활성화한다. PRESENT 클릭이 다음 카드로 관통하지 않는다.
5. `COMMAND_QUEUED / REPLACED / CANCELED / COMMITTED / APPLIED / EXPIRED` 기록을 사용한다. APPLIED는 resolver가 행동에 반영한 때만 남긴다.
6. CP·마나 비용은 없다. 지불하는 대가는 해당 국면에서 다른 지시를 못 쓰는 것과 공간·시간의 약점이다. ‘아낄 자원’이 없는 MVP에서 아껴 쓰라는 설명은 하지 않는다.
7. 하프타임에도 다음 국면 예약은 하나다. 요약 제안 버튼을 여러 번 눌러도 마지막 예약이 무엇인지 그대로 보여준다.

### 4.2 상대와 참모

상대는 같은 여섯 지시·범위·약점을 사용한다. `prepareEncounter()`가 FLOW 시작 전에 이번 의도를 정하고 고정한다. 입력에는 현재 공개된 위치·점수·matchSeconds·이전 확정 지시만 들어간다. 사용자 pendingCommand나 아직 공개하지 않은 난수 결과를 읽지 않는다. 이번 카드에 즉시 맞춤 대응하는 상대를 만들지 않는다.

초기 상대는 세 프로필(측면 전개, 중앙 침투, 신중한 복귀)을 규칙으로 구현한다. 정상 모드는 관측 가능한 빈 공간을 우선하고, 같으면 상대 결정용 RNG로 고른다. 다음 국면에는 공개된 사용자 패턴에 반응할 수 있다. 난이도는 예고 선명도·과거 패턴 활용·선택 다양성으로 조정하며 숨은 능력치 보너스는 쓰지 않는다.

기본 난이도의 예고는 상대 카드명과 숨은 숫자를 정답처럼 공개하는 대신, 앞으로 이동한 압박자·열린 측면·중앙 러너를 화면에 보여준다. 참모의 관측 사실은 항상 맞아야 한다. 플레이어는 어느 위험을 감수할지 고른다. 낮은 난이도에서는 같은 의도를 문장으로 더 명확히 설명할 수 있다.

참모는 `관측 사실 → 제안 → 대가`만 말한다. “오른쪽에 두 명이 붙었습니다. 반대편으로 바꿀 수 있지만 전달이 깁니다”처럼 근거를 `evidenceIds`로 연결한다. 전반 전체 요약은 전반 기록을 집계한다. 추측을 사실로 쓰거나, 지시를 냈다는 이유로 실패/성공을 주장하지 않는다. MVP는 LLM 생성 대사 없이 검증된 템플릿으로 충분하다.

## 5. 상태·행동·판정·표현의 경계

### 5.1 최소 상태

`MatchState`는 version, seed, sessionId, matchSeconds, half, score, possessionTeam, ball, players, tacticalExposure, encounterIndex, currentEncounter, rngStates, eventLog를 가진다. 선수는 id/team/role/active/position과 pass/carry/shoot/defend/keep의 게임용 능력치만 시작한다. 능력치 범위는 0~100, MVP 기본 두 팀은 대칭으로 둔다. 현재 22개 능력치 전체를 이식하지 않는다.

평면 좌표는 기존처럼 미터 x∈[-52.5,52.5], z∈[-34,34]를 사용한다. 방향은 팀별 ±1, 후반에 반전한다. 연출 좌표는 이 상태와 사건 비트에서만 변환한다. 주요 행동에는 2~6명의 배우를 크게 보여주고 작은 전술 필드에는 활성 선수 전체를 표시한다. 큰 장면이 매번 22명을 그릴 필요는 없다.

공 모드는 `CONTROLLED / GROUND_PASS / AERIAL_PASS / SHOT / LOOSE / RESTART`를 명시한다. 소유자는 최대 한 명이다. 공중볼은 도착·공중 경합·낙하 사건 중 하나를 거쳐야 소유가 바뀐다. 바닥 투영 거리만 보고 공중볼을 잡지 않는다. 비행 높이 자체의 정교한 물리 적분은 필요하지 않다.

### 5.2 행동과 경합의 기본 모형

공격의 최소 행동은 운반, 지상 패스, 전환 패스, 크로스, 슛, 안전한 되돌리기다. 수비는 압박 접근, 길목 차단, 경합, 골 방향 복귀다. 후보는 위치·역할·공 상태로 합법성을 먼저 검사하고, 감독 지시는 후보 생성/우선순위/위치를 바꾼다. 합법적 후보가 없으면 가까운 안전한 운반·복귀 또는 기본 유지로 이어진다. 무조건 슛이나 공 소멸로 끝내지 않는다.

초기 일반 경합식은 `p = clamp(0.50 + (attackRating - defenceRating) / 120, 0.10, 0.90)`으로 한다. 이 값은 실축의 경험식이 아니라 조정 가능한 게임 규칙이다. 공격/수비 rating은 행동에 대응하는 능력치, 위치에서 계산한 여유 공간, 패스 길의 수비, 실제 지원 인원으로 구성한다. 공간·지원 보정의 합은 각 측 ±20을 초기 상한으로 둔다. **카드 ID 자체를 rating 보너스로 더하지 않는다.** 구체적인 거리 임계값은 rules.json에 두고 첫 12개 비교 장면의 행동 결과로 조정한다.

패스 경합은 수신·차단·굴절로, 돌파 경합은 전진·탈취·루즈볼로, 슛은 골문 방향 성공과 GK 경합의 두 단계로 구분한다. 슛의 사전 성공 가능성과 실제 outcome은 같은 기록에 남긴다. M1은 지상 패스·돌파·슛/GK, M3에서 크로스·공중볼·재개로 넓힌다. 임시 단순화는 파일과 완료 상태에 명시하고 완성된 기능처럼 문구를 만들지 않는다.

포지셔닝은 법칙에서 창발해야 한다는 연구 제약을 새 MVP에 강요하지 않는다. 역할별 합법적 목표점과 공간 노출을 명시적으로 설계할 수 있다. 다만 장면마다 전원을 원위치로 초기화하거나 카드마다 완성된 승리 영상을 고르는 방식은 쓰지 않는다.

국면 선택은 `재개 → 루즈볼 → 골문 경합 → 측면/중앙 경합 → 안전 전개` 순으로 현재 상태의 조건을 검사한다. encounter 템플릿은 출연 배우·카메라·가능한 행동만 제안하고 점수·소유·좌표를 덮어쓰지 않는다. 고정 비교 장면 외에는 장면 번호에 따라 공격/수비가 자동 교대하지 않는다. 한 국면은 최대 3개의 경합과 4개의 핵심 공개 비트로 제한한다. 마지막에 선언된 PK는 그 한도 안에 해결 슬롯을 예약한다. 남은 루즈볼·일반 재개는 명시된 상태로 다음 국면에 넘기며, 재귀적인 새 경합 호출을 만들지 않는다.

### 5.3 판정 기록과 한 번의 커밋

```js
EncounterResolution = {
  id, encounterId, rulesVersion, beforeHash,
  opponentIntent, committedCommand,
  appliedChanges, // 이동·후보·우선순위·노출의 실제 변화
  contests,       // actor IDs, 위치, rating 근거, 확률, 판정 draw
  events,         // shotId 등을 공유하는 실제 사건
  beats,          // 사건별 poseFrom/poseTo, 공 궤적, 공개 시점
  nextState, afterHash, deltaMatchSeconds
};
```

`resolveEncounter(snapshot, commands, rng)`는 카드 선택 창이 닫힌 뒤 한 번 호출한다. 순수 함수의 결과 기록을 확인한 다음 코어가 state를 한 번 갱신한다. `resolvedEncounterIds` 또는 현재 encounter ID의 완료 상태로 중복 커밋을 차단한다. 렌더러의 `onComplete`, 이미지 `onload`, 동영상 재생 종료가 점수·난수·카드 적용을 실행하면 안 된다.

판정 RNG, 상대 선택 RNG, 표현 선택은 분리한다. 표현은 가급적 event ID에 따른 순환 선택으로 한다. 문구 개수·영상 길이·화면 프레임 수가 판정 draw를 바꾸지 않는다. 명령 재생 기록은 벽시계 클릭 시간이 아니라 encounter ID와 최종 확정 명령을 저장한다.

경기 비교 해시는 상태·규칙 버전·정규화한 사건을 대상으로 한다. 렌더 커서, 벽시계, 세션 취소용 sessionId, 로컬 제출 UUID는 제외한다. 사건 ID는 국면/사건 순번에서 안정적으로 만든다. 같은 시드와 명령을 새 세션에서 재생해도 해시가 같아야 한다. 경기 중 rulesVersion/데이터는 고정하고 새 규칙은 새 경기부터 적용한다.

복원 스냅샷은 MatchState뿐 아니라 현재 단계, flowPlan/COMMAND 스냅샷, pendingCommand, 이미 확정된 resolution, 공개 비트 커서, 남은 선택/재생 시간도 함께 저장한다. 저장 시점에 해상되지 않은 명령을 조용히 확정하거나 완료된 경합을 다시 뽑지 않는다. 복원 직후는 일시정지로 보여주고 재개 입력을 받는다.

득점·슛·유효슈팅·선방·소유 변경·재개는 events에서만 집계한다. SHOT에는 시점·위치·공격팀·선수·shotId를 기록하고, GOAL/SAVE/MISS가 그 shotId를 참조한다. 유효슈팅은 한 shotId당 최대 한 번이다. 현재 xG 근삿값은 새 제품의 UI·보상에 가져오지 않는다. 검증된 필요가 생기면 별도 기능으로 추가한다.

### 5.4 다음 상태와 축구 규칙의 최소 범위

- 패스 차단은 차단 지점과 차단 선수로 소유를 넘긴다. 실패가 자동으로 상대 슛·골이 되지 않는다.
- 지시로 전진한 선수와 노출된 공간은 다음 국면에 남는다. 복귀는 행동이며, 장면 전환으로 순간 복귀하지 않는다.
- 태클 실패의 제쳐짐은 해당 경합 나머지 비트 동안 재경합을 금지한다. 다음 국면에도 늦은 복귀 위치가 남는다.
- 오프사이드는 패스 출발 스냅샷의 상대 진영·공·두 번째 최종 수비수 조건과 실제 수신자 관여를 사용한다. 골킥·코너·스로인 직접 수신 예외를 포함한다. 같은 합법성 함수를 행동 후보와 판정에서 사용한다.
- 득점은 슛 사건의 골라인 통과 결과로 한 번 발생한다. 직후 상대 킥오프 재개 상태를 만든다.
- 아웃은 마지막 터치에 따라 스로인·골킥·코너로 이어진다. 재개 위치 전환은 명시적 RESTART 컷으로 보여준다.
- M3에는 직접 프리킥·PK를 작은 사건 규칙으로 포함한다. PK도 별도 슛 기록과 결과 컷을 사용한다. 반칙/PK 발생은 카드 정답률을 맞추기 위한 보정 수단으로 쓰지 않는다. 경고/퇴장·인원 부족·GK 대체는 함께 L1으로 미뤄 규칙 일부만 노출하지 않는다.
- 경계에 걸린 국면은 잠근 행동 묶음을 끝낸 뒤 하프타임/종료한다. 그 묶음에서 선언된 PK는 같은 묶음의 PK 해결 비트까지 처리한다. 종료 뒤 새 슛·새 카드·새 재개 판정을 시작하지 않는다.

## 6. 이미지와 경기 화면의 제작 계약

화면은 위 점수/시간, 큰 액션 스테이지, 작은 전술 필드, 아래 카드 세 장과 유지·예약 슬롯을 기본으로 한다. 참모는 한두 문장 보조 패널이다. 거대한 중계 피드가 경기 장면을 밀어내지 않는다. 카드 프레임·문구·번호·점수·시간은 코드로 그린다.

그림은 오리지널 스포츠 만화풍의 제작 초안으로 시작한다. 참조 게임의 픽셀 해상도·기존 캐릭터·팀 로고·대사를 복사하지 않는다. 화면 문법과 화풍을 같은 결정으로 취급하지 않는다. 이번 이미지 시안은 스타일·분리 제작 가능성을 확인하는 초안이며 지원이 특정 시안을 선택하면 그 원본을 고정한다.

### 6.1 에셋 최소 목록

| 종류 | 최종 목표 수 | 원본 규격·투명도 | 쓰임 |
|---|---:|---|---|
| 경기 배경 | 3 | 약 1920×1080 이상, 불투명 | 측면 필드·골문·벤치. 선수·공·UI 없음 |
| 필드 선수 포즈 | 8 | 약 1024px, 실제 RGBA | 두 팀 × 준비/운반/킥/경합·반응. 우선 공용 배우 |
| GK 포즈 | 4 | 약 1024px, RGBA | 두 팀 × 준비/다이빙. 공은 별도 |
| 감독 초상 | 4 | 약 512px, RGBA | 두 감독 × 관찰/지시 |
| 카드 삽화 | 6 | 약 768×512, 글자 없음 | 확정된 6개 지시의 동작 |
| 합계 | 25 | 생성 호출 수와 다름 | 동일 원본 크롭·코드 합성으로 재사용 가능 |

첫 슬라이스는 배경 1, 공격/수비/GK 배우 각 1, 카드 삽화 2로 검증한다. 이후 필요한 변형만 만든다. 모든 선수의 고유 얼굴, 모든 경기 결과의 영상 파일을 만들지 않는다.

공, 궤적, 속도선, 그림자, 대상 강조, 전술 필드 선, 등번호는 코드가 소유한다. 기본 동작은 이동·작은 확대·포즈 교체다. 이미지 속 공과 코드 공이 둘 다 보이면 실패다. 성공·차단·선방·빗나감은 서로 다른 종료 위치와 비트를 보여준다. 배경에 그려진 골문·잔디선은 카메라별 지평선/골문 영역과 맞춰 사용한다. 실제 상태와 맞지 않는 배경 위에 수비수·공을 임의로 배치하지 않는다. 초기에 같은 카메라와 필요 시 좌우 반전으로 제한한다.

타임라인에는 모든 비트의 사건 ID, 배우, 공 위치, 카메라, 공개할 문구를 기록한다. 큰 경기 화면·전술 필드·중계·점수판은 같은 비트 커서를 사용한다. 경기 화면에 공이 왼쪽에 있는데 전술 필드에는 다른 위치가 표시되는 독립 연출을 만들지 않는다. 큰 화면은 카메라 투영을 달리할 수 있으나 actor/ball/outcome은 같다.

### 6.2 생성·수정·사용 규칙

- Higgsfield MCP는 현재 연결을 확인했다. 직접 이미지 생성, 참조 이미지 입력, 투명 배경 출력을 시험한다. 가용 모델·가격은 실행할 때 다시 조회한다.
- 현재 확인한 `gpt_image_2_5`의 flare/high/2k 한 장 견적은 3크레딧이다. 이 가격을 미래 고정 가격으로 가정하지 않는다.
- 완성된 이전 작업 ID를 다음 생성의 참조로 사용해 유니폼·외형·광원을 유지한다. 플레이 중 생성 API 호출은 0회다.
- `autosprite`는 실제 가용 모델로 확인했지만 아직 품질 검증 전이다. 투명 배우가 준비되면 짧은 준비/달리기 포즈 한 종만 비용 확인 후 시험할 수 있다. 실패해도 정적 포즈와 코드 동작으로 전체 게임이 돌아가야 한다.
- 일반 동영상은 MVP 필수에서 제외한다. 필요하면 결과와 무관한 경기 시작·벤치 컷 한 종만 시험한다. 패스 접촉·공 궤적·득점은 고정 영상으로 판정하지 않는다.
- 생성 원본은 `docs/director-probes/`, 승인해 사용하는 출하 파일은 구현 시 `assets/director/`로 둔다. 원본을 덮어쓰지 않는다.
- 자산 기록에는 ID/용도/참조/프롬프트/모델·설정/작업 ID/파일 해시/픽셀 크기/alpha/바닥 기준점/검토 상태/과금을 남긴다. 원격 URL만 저장해 만료에 의존하지 않는다.
- 체크무늬가 그려진 그림을 투명 이미지로 판정하지 않는다. 알파 채널·배경 경계·손발·유니폼 일관성을 실제 파일과 렌더에서 확인한다.
- 한 자산의 최초 생성 후 수정은 기본 한 번, 핵심 대표 인물·배경만 두 번까지. 반복 실패하면 구도를 단순화하거나 기존 자산을 재사용한다.

2026-09-22 제작 검증에서는 장면 시안·빈 경기장·분리 선수 총 3장을 만들었다. 선수 파일의 실제 알파(0~254), 배경과의 브라우저 합성, 흰색/어두운 바탕의 경계를 확인했다. 초기 원본은 2K급이고 사용할 파일의 크기·바닥 기준점·카메라 보정은 M2에서 정한다. [제작 기록](director-probes/README.md)과 [합성 확인 페이지](director-probes/preview.html)에 검증 범위를 남겼다. 이 결과는 투명 정적 자산 경로만 입증하며, 애니메이션이나 플레이 구현의 완료를 뜻하지 않는다.

### 6.3 300크레딧 누적 예산

| 용도 | 상한 |
|---|---:|
| 스타일·기준 이미지·첫 장면 제작 검증 | 30 |
| 사용할 정적 자산 제작 | 120 |
| 결함 수정·일관성 재생성 | 70 |
| 선택적 스프라이트 또는 짧은 영상 시험 | 30 |
| 실제 화면에서 발견되는 결함 예비비 | 50 |
| 전체 | **300** |

이번 계획 작성에서 쓴 크레딧도 300에 포함한다. 300은 소진 목표가 아니다. `docs/director-probes/generation-ledger.json`에 누적 예상·확정 사용·대기 중 예약액을 남긴다. **확정 사용 + 진행 중 예상 + 새 견적 ≤ 300**인 경우만 제출한다. 비용이 불명확한 작업, 300을 넘기는 작업, 실패 여부가 불명확한 중복 제출은 하지 않는다. 잔액 차이는 동시 사용의 영향이 있을 수 있으므로 작업별 견적/영수증과 대조한다. 보조 에이전트는 유료 작업을 제출하지 않고 주 에이전트 한 명이 장부를 관리한다.

에셋 한도가 소진되거나 생성 서비스가 막히면 이미 확보한 그림과 정적 포즈로 구현을 계속한다. 새로운 과금 승인이 필요한 작업만 중단한다. 자동 구독·크레딧 구매는 승인 범위가 아니다.

## 7. 기존 코드와 새 코드의 처리

기준 원격 main: `4cfa70247fe392271961467c7d5850e9d1d12dbb` (2026-09-22 확인). 조사한 기존 작업 디렉터리는 `.claude/worktrees/thelongsilence-game-analysis-da7f74`의 `931c083a9f65bea3de6e271476e7a55dffa25715`이며 파일 트리가 같다. 작성 당시 루트는 `feature/continuous-match-engine`의 `6647293`다. **구현을 오래된 루트 HEAD 위에서 시작하지 않는다.**

계획과 제작 시안은 루트 작업 폴더에 추가했다. 다음 실행 시 최신 원격 상태를 읽고 사용자 변경을 확인한다. 최신 main에서 `codex/` 작업 브랜치의 격리된 작업 디렉터리를 만들고 이 계획·시안·장부 및 명시된 문서 변경만 옮긴다. 원래 루트의 미커밋 파일을 삭제·되돌리거나 기존 detached 작업 디렉터리를 임의로 전환하지 않는다. 기준 main이 달라졌으면 변경된 관련 영역만 재조사한다.

| 대상 | 처리 |
|---|---|
| `js/game/*`, `viewer.html`, `data/policy.json`, `sim/selfplay*` | 연구 경로로 보존. 새 제품에 모든 물리·학습 버그 수리 완료를 요구하지 않음 |
| `js/engine/*`, `index-legacy.html` | 흐름 참고. 누락 데이터·결과표 교체·표현 RNG 결합 때문에 그대로 복구하지 않음 |

새 책임은 `js/director/match.js`(상태·단계), `resolve.js`(행동·경합·사건), `cards.js`(합법성·예약·효과), `scenario.js`(국면 준비·상대 의도), `replay.js`(기록/복원), `main.js`(입출력 연결) 정도로 시작한다. 화면은 `js/ui/scene-player.js`와 `main.js`, 데이터는 `data/director/rules.json`, 카드/장면/문구는 해당 순수 모듈이 소유하고 진입점은 `director.html`이다. 초기 후보였던 별도 replay/view 및 작은 JSON 다섯 개는 실제 독립 책임이 없어 만들지 않는다. 책임이 실제로 생기기 전에 빈 추상 계층을 늘리지 않는다.

초기에는 director.html로 검증하고 M6 통과 시 index.html의 기본 진입점만 전환한다. 연구 viewer는 직접 링크로 남긴다. 코드 삭제는 별도 정리 작업으로 미룬다.

| G1 결정론 | 고정 20개 시드 × 유지/공격/수비/교대의 명령 전략 4종을 각각 두 번 재생해 사건·최종 상태 해시 일치. 문구/에셋 순서만 바꿔도 판정 불변. |
| G2 사건·규칙 | 한 슛당 결과/유효슈팅 중복 0, 한 공 소유자 ≤1, 유효한 선수 참조, 재개/루즈볼 회수는 FLOW 진입 경계에서 사건으로 확정하고, 진행 중에는 소유 변경 없는 FLOW, 재개·득점·하프타임·종료 정확히 한 번. 패스 순간 오프사이드 및 재개 예외 고정 장면 통과. |
| G3 카드 인과 | 6장 각각 이득이 드러나는 장면과 약점이 드러나는 장면 1개씩, 총 12개. modifier 존재가 아니라 이동·후속 행동 후보·소유·시간·노출 중 실제 변화 증명. 합법성 실패/중복/취소/만료 포함. |

| G7 완주·복원 | 100개 시드 × 전략 4종, 400경기 전부 유한한 20~28국면에 종료. 페이싱은 가상 presentation clock으로 8:20~11:32 범위를 검사하고 브라우저 기본 무스킵 한 경기로 확인한다. 400경기를 실제 벽시계로 기다리지 않는다. 명령 직전·직후·결과 재생 중 스냅샷 복원 3곳에서 재판정/중복 없음. |

카드의 우열을 승률 하나로 단정하지 않는다. 12개 비교 장면에서 기대하는 구조 변화는 결정론적으로 검사하고, 확률 경합은 고정 시드 묶음에서 반복해 우연한 단일 득점과 분리한다. 모든 상황에서 같은 카드가 나머지를 지배하면 그 카드의 공간·시간 대가를 검토한다. 실축 골/패스 평균에 맞추기 위해 결과를 덮어쓰거나 패배를 보정하지 않는다.

자동 검사는 새 게임을 대상으로 한다. 기존 100경기 안정성·realism 검사가 통과했다는 이유로 새 제품을 통과 처리하지 않는다. 새 게임과 무관한 구 엔진의 실패를 고치느라 M1을 막지도 않는다.

### 9.1 사람 검증

기술 QA 후 비교 장면 5개를 지원이 볼 때, 최소 4개에서 상대의 준비·선택 이유·바뀐 행동·대가를 설명할 수 있는지 확인한다. 그 뒤 한 경기에서 다시 해보고 싶은 판단이 생겼는지 의견을 받는다. 이것은 제안된 제품 게이트이며, 에이전트가 대신 통과시킬 수 없다.

부재 중 실행의 완료 보고는 `구현 및 자동/브라우저 검증 완료, 사람 플레이 검증 대기`처럼 분리한다. 준비된 검증 장면을 남기고, 사람 검증을 못 했다는 이유로 이미 승인된 구현을 중간에 멈추지 않는다.

## 10. 예외 처리·실패 시 대안·중단 조건

| 상황 | 기본 처리 |
|---|---|
| 카드 입력 없음 | 기본 유지로 정상 진행 |
| 상대 진영·대상·역할이 변해 예약 무효 | 취소 이유 기록, COMMAND에서 다시 선택 가능; 최종 확정 시 무효면 유지 |
| 이미지/영상 로드 실패 | 동일 사건의 기존 정적 그림 또는 도형+사실 문구로 표시. 결과/RNG 변경 금지 |
| 스킵·중복 클릭·탭 복귀 | 같은 resolution을 끝까지 공개. 새 판정 호출 금지 |
| 새로고침 | 같은 rulesVersion 스냅샷과 확정 기록 복원. 명령창 타이머도 보존; 결과 중이면 기존 기록 재생 |
| 저장 버전 불일치 | 조용한 변환 대신 호환 불가 안내와 기록 내보내기/새 경기. 저장 마이그레이션은 별도 결정 |
| 첫 장면이 읽히지 않음 | 세 카드·한 공격/수비로 줄인 상태에서 관측/도착/대가를 보강. 자산 수·모델 규모 확장 금지 |
| 생성 예산 부족/서비스 실패 | 승인된 자산과 정적 동작으로 진행, 추가 유료 작업만 보류 |
| 관련 자동 검사 실패 | 실패 장면 고정 → 해당 계약을 수정 → 그 검사와 영향 범위만 재실행 |

다음 상황에는 증거·현재 변경·안전한 다음 선택을 남기고 멈춘다: 사용자 변경을 덮어쓸 위험, 계획에 없는 외부 쓰기·배포·새 의존성, 300크레딧 초과가 필수인 요구, 핵심 상태 계약으로 해결할 수 없는 제품 정책 충돌, 같은 원인으로 세 번 연속 실패해 안전한 대안도 없음. 단순한 구현 선택·배치·명명·정적 이미지 대체는 묻지 않고 결정한다.

핵심 재미가 확인되지 않았다는 이유로 실축 연구나 새 카드 경제로 방향을 바꾸지 않는다. 첫 장면의 문제와 실제 관측을 기록해 제품 검토 대상으로 남긴다.

## 11. 중단 후 재진입과 결과 보고

구현 시작 시 `docs/director-progress.md`를 만든다. 현재 마일스톤, 작업 디렉터리/브랜치/기준 SHA, 사용자 변경분, 마지막 통과 명령, 남은 실패와 재현 시드, 실행 URL, 다음 한 작업, 에셋 장부 경로를 기록한다. 단계가 끝날 때만 갱신해 로그 잡음을 줄인다.

재진입 순서는 진행 문서 → git 상태/현재 SHA → 새 사용자 지시 → 마지막 실패 장면/검사 → 다음 단계다. 완료된 조사와 과거 연구 테스트 전체를 매번 반복하지 않는다. 에셋 작업은 장부의 pending job ID를 먼저 확인하고, 응답 유실을 새 생성 요청으로 대체하지 않는다.

최종 보고는 무엇이 플레이 가능해졌는지 먼저 말하고, 실행 경로·완료 게이트·미확인 사람 검증·Higgsfield 실제/예약/잔여 예산을 남긴다. 생성 그림이 있다는 사실과 게임에 연결돼 있다는 사실을 분리한다. 계획서 체크박스를 구현 증거로 쓰지 않는다.

## 12. MVP 이후의 확장 순서

| 단계 | 조건 | 다음 범위 |
|---|---|---|
| L1 선택의 깊이 | MVP 사람 검증에서 핵심 인과가 읽힘 | 실제 선수 교체, 소수 선수 특성, 피로/거츠 중 필요한 자원 하나. 경고/퇴장은 인원 부족·GK 대체·조기 종료 계약까지 함께 설계. 기존 무작위 영구 버프 교체는 계승하지 않음 |
| L2 상대와 콘텐츠 | 여섯 카드의 장단점이 안정 | 추가 팀·상대 스타일·특수한 경기 상황·짧은 서사. 기존 카드와 구별되는 행동만 추가 |
| L3 모델 연구 연결 | 규칙/게임 계약과 평가 장면이 고정 | 기존 연구 모델을 행동 선택 후보로 A/B 비교. 모델이 없어도 제품 실행·판정은 유지 |
| L4 유통 확장 | PC 한 경기 품질과 자산 예산 검증 | 모바일·패키징·배포를 별도 계획/승인으로 진행 |

후속 단계는 이번 무인 실행의 범위가 아니다. MVP 뒤 새로운 요구를 추측해 시즌·과금·온라인 기능까지 진행하지 않는다.

권고가 달랐던 선택 창은 **기본 6초+일시정지**로 통일했다. 무제한 판단 시간과 정확한 10분 종료를 동시에 요구하지 않는다. 카드 확정 이후 다음 국면 예약까지 받는 제안은 MVP에서 채택하지 않았다. PRESENT에서는 카드가 비활성이고 다음 FLOW에서 다시 예약한다. 시각 재생 종료가 상태 커밋을 실행하는 방식도 채택하지 않았다. RESOLVE에서 한 번 커밋하고 표현은 기록 공개만 담당한다.

최종 통합에서는 최초 시연을 3국면 82초로 구체화하고, FLOW의 숨은 소유 전환을 제거했다. 경고/퇴장은 교체·인원 부족까지 연결되는 별도 기능이라 L1으로 옮겼다. 감독 카드 6장의 인과를 검증하기 전에 전체 축구 규칙을 다시 완성하는 경로로 늘어나지 않게 한 선택이다.
