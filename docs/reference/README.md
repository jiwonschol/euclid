# 표적 (평가 레퍼런스)

goal-harness 루프가 "완성됐는가"를 판정할 때 **나란히 놓고 대조하는 것들**이다.
구현 레퍼런스(무엇처럼 만들까)가 아니라 **평가 레퍼런스**(완성 여부를 무엇과 대조할까)다.

루프도 심판도 이 디렉터리의 파일을 **수정할 수 없다**. `.claude/loop/guard.mjs` 가 SHA-256 으로 고정하고,
회차마다 대조해 불일치 시 주행을 중단한다.

| 파일 | 무엇의 표적인가 | 누가 읽는가 |
|---|---|---|
| `target-pitch.png` | 판이 축구로 읽히는가 — 진형·간격·GK 위치·22명의 가시성 | 심판(이미지로 직접 대조) |
| `match_stats.json` | 경기 수치가 실제 축구 범위인가 | `sim/realism-lint.mjs`(기계) |
| `match_stats.md` | 위 수치의 사람 읽는 판 + 출처 | 심판 |
| `../match_engine_v1_plan.md` §0.1 | 게임 정체성 — 대응이 읽히는가, 텍스트가 코어인가 | 심판 |

## target-pitch.png — 디자이너 제공 (필수)

2026-07-29 디자이너가 지정한 스냅샷. **이 파일이 없으면 루프는 주행하지 않는다** (§6 교정 관문에서 중단).

이 이미지에서 심판이 읽어야 할 성질:

1. **22명이 동시에 판 위에 보인다.** 어느 순간에도 선수가 사라지지 않는다.
2. **진형이 진형으로 보인다.** 공 주변에 뭉치지 않고, 라인이 유지되고, 폭이 벌어져 있다.
3. **양 골키퍼가 각자 골문 앞에 있다.** 필드로 나와 돌아다니지 않는다.
4. **공의 위치가 판을 조직한다.** 공을 중심으로 양 팀이 서로 다른 의도로 배치되어 있다.

심판은 매 회차 `.claude/loop/runs/<회차>/pitch-*.png` 를 이 이미지와 **나란히 열어** 판정한다.
기억으로 대신하는 것은 금지 — 판정문에 두 그림의 구체적 차이를 적어야 한다.
