# 실제 축구 기준 (표적의 수치 판)

수치 정본은 옆의 `match_stats.json` 이다. 이 문서는 **심판이 읽는 판**이고, 각 숫자가 왜 그 값인지를 적는다.
루프는 이 문서도 `match_stats.json` 도 수정할 수 없다 — 임계값을 낮춰 통과시키는 것이 가장 값싼 도주로이기 때문이다.

## 한 경기 90분, 양팀 합계

| 지표 | 기준 | 왜 이 값인가 |
|---|---|---|
| 골 | 2.7 | 유럽 1군 리그 경기당 총득점 장기 평균대. 2.5 미만이면 답답하고 3.5 초과면 난타전이다 |
| 슛 | 24 | 팀당 12. 이보다 훨씬 많으면 "아무 데서나 쏜다"는 뜻이다 |
| 유효슈팅 | 8.4 | 슛의 약 35%. 이 비율이 무너지면 슛 판정이나 GK 둘 중 하나가 틀렸다 |
| xG / 슛 | 0.10 | 평균적인 슛 하나의 득점 기댓값. **0.3 을 넘으면 xG 모델이 고장난 것이다** |
| 파울 | 21.5 | 이보다 훨씬 많으면 태클 판정이 과하다 |
| 코너 | 10.2 | **0 에 가까우면 코너가 아예 발생하지 않는 것이고, 그러면 축구가 아니다** |
| 오프사이드 | 4.0 | 0 이면 규칙이 없는 것이고, 10 을 넘으면 공격 라인이 상시 넘어가 있는 것이다 |
| 패스 | 880 | 팀당 440. 이 수가 낮으면 "두 번 주고 슛"이 반복된다는 뜻이다 |

## 판이 축구로 읽히는가

`target-pitch.png` 에서 **눈으로 확인되는** 성질을 수치로 옮긴 것이다. 그림이 정본이고 이 표는 그 근사다.

| 관측 | 기준 | 무엇을 막는가 |
|---|---|---|
| GK ↔ 자기 골문 거리 | p95 ≤18m, 최대 ≤30m | 골키퍼가 필드로 나와 돌아다니는 것 |
| 공 10m 안 필드 선수 | p95 ≤6명 | 22명이 공을 따라 한 덩어리로 몰려다니는 것 |
| 진형 ↔ 공 위치 상관 | **0.55 ~ 0.92** | 하한: 공이 움직여도 진형이 안 따라오는 것. **상한: 팀이 공에 강체처럼 붙어 평행이동하는 것** |
| 팀 폭 (z 스팬) | ≥30m | 좁은 중앙에 일자로 늘어서는 것 |
| 팀 깊이 (x 스팬) | 30~45m | 너무 늘어지거나 너무 압축되는 것 |

상관계수를 **밴드**로 둔 이유: 2026-07-29 실측이 r=0.98 이었다. 하한만 뒀다면 이 값은 만점이지만,
실제로는 열 명이 공 x좌표에 붙어 통째로 움직인다는 뜻이라 표적 이미지와 정반대다.
**지표를 올리는 가장 쉬운 방법이 축구다움을 떨어뜨리는 방향일 때, 그 지표는 밴드여야 한다.**

## 중계 텍스트

| 관측 | 기준 | 왜 |
|---|---|---|
| 템플릿 토큰 누출 | **0줄 (치명)** | `{T}`·`#의` 가 화면에 그대로 나오면 다른 무엇도 볼 필요가 없다 |
| 근접 20줄 중복 | ≤1.5% | 같은 문장이 몇 줄 간격으로 반복되면 읽는 사람이 즉시 알아챈다 |
| 분당 줄 수 | 8~20 | 8 미만은 근거가 부족하고, 20 초과는 읽기 전에 흘러간다 |

## 게임으로서의 형태

| 관측 | 기준 | 왜 |
|---|---|---|
| 실플레이 시간 | 9~11분 | 디자이너 지정. 한 판이 앉아서 끝낼 수 있는 길이여야 한다 |
| 분기점 밀도 | 8~20회 / 10분 | 30~75초에 한 번. 더 잦으면 반응할 틈이 없고 더 드물면 볼 것이 없다 |
| 개입 델타 (승점) | **+0.30 ~ +1.50** | 0 이면 카드는 장식이다. 1.5 초과면 카드만 내면 이기는 슬롯머신이다 |
| 개입 델타 (득실) | **+0.30 ~ +2.00** | 위와 같은 이유로 밴드 |

2026-07-29 실측 개입 델타는 **+0.20 승점**(무개입 1.27 → 개입 1.48, n=40×2)이었다.
즉 이 시점의 euclid 는 카드를 내든 안 내든 결과가 거의 같았다 — 축구 시뮬로서는 몰라도 **게임으로서는 성립하지 않았다.**
